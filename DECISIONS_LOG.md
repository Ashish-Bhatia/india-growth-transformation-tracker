# Methodology and Architecture Decisions Log

| Decision ID | Decision | Type | Status | Rationale |
|---|---|---|---|---|
| DECISION-METH-001 | Treat the project frameworks as a layered system: Research Charter governs project purpose/principles; specialized foundational frameworks govern their named domains; Execution Protocol governs operational execution; GitHub Specification governs implementation architecture. | Governance | Proposed resolution | No single explicit precedence matrix exists in the source set. This resolves overlap without replacing domain-specific authority. |
| DECISION-METH-002 | Keep source authority/tier separate from evidence grade. | Evidence/data | Proposed resolution | The source documents use different concepts. A source's authority is not the same as the strength of its support for a particular claim. |
| DECISION-METH-003 | Preserve exact dates in the database and use standardized term labels for presentation. | Time | Proposed resolution | Source frameworks require exact event/implementation dates and also use broad term labels. Database storage of exact administration dates does not settle the unresolved analytical term-window convention. |
| DECISION-METH-004 | Do not implement final sector weights until the scoring methodology is explicitly finalized. | Scoring | Active | Version 1.0 explicitly leaves final sector weights and composite formulas for later work. |
| DECISION-DB-001 | Use generated numeric primary keys plus immutable machine-readable `code` fields as stable external identifiers. | Database | Active | The schema requires generated stable identifiers and separately requires human-readable codes. Display names are not identifiers. |
| DECISION-DB-002 | Do not enable a PostgreSQL extension in the initial foundation because the Project Sources do not explicitly approve a required extension. | Database | Active | The initial schema does not require extension-specific functions. This avoids an undocumented infrastructure dependency. |
| DECISION-DB-003 | Implement P1-P5 materiality as a controlled vocabulary without descriptive labels. | Database/methodology | Active pending ISSUE-001 | The two Project Sources use incompatible descriptive labels. The database preserves the numeric scale without silently choosing a description. |
| DECISION-DB-004 | Implement the domain entity and relationship, but do not seed domains until an authoritative complete domain registry is available. | Taxonomy | Active | The Master Database Schema requires domains, but the Master Research Taxonomy does not provide a complete domain-level seed list. |
| DECISION-DB-005 | Seed India plus the 28 States and 8 Union Territories required for the geographic foundation; keep the country registry extensible and do not create a peer basket before analytical peer selection. | Geography | Active | The schema requires national, State/UT and international support. The Project Sources do not define a fixed peer basket. |
| DECISION-DB-006 | Keep scoring infrastructure configurable but seed no final weights, normalization or composite formulas. | Scoring/database | Active | ISSUE-005 remains unresolved. The database must support future scoring without converting provisional architecture into methodology. |
| DECISION-DB-007 | Use transactional forward-only migrations. Failed migrations roll back. Already-applied migrations are immutable; production rollback requires a new forward migration or approved database restoration. | Database governance | Active | This implements the source requirement to use migrations and preserve reproducibility without destructive schema edits. |
